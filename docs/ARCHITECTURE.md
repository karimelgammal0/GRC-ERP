> آخر مراجعة: 2026-11-24 — على كود `karimelgammal0/grc-erp` (commit `523ffd0`).
> الملف ده «خريطة النظام»: بيشرح كل موديول وتفريعاته وإمكانياته، وإزاي الموديولات بتتربط ببعض وبدليل الحسابات.

## 1) نظرة عامة

| البند | التفصيل |
|---|---|
| النوع | تطبيق ويب عربي RTL + PWA (بيتثبّت على الموبايل باسم «Seif GRC») |
| الخادم | Node ≥ 20 + Express 4 (ES modules) |
| قاعدة البيانات | PostgreSQL — Supabase في الإنتاج (`DATABASE_URL`)، أو PGlite مضمّن محلياً/اختبارات |
| الواجهة | JavaScript خام (بدون frameworks) — `h()` لبناء الـ DOM، صفحات لكل شاشة |
| الاستضافة | Railway (`seifgrc.up.railway.app`) + Supabase |
| الحجم | ≈ 3,300 سطر سيرفر + 570 سطر schema (60 جدول) + 2,200 سطر واجهة + 610 سطر اختبارات |
| الاختبارات | 5 ملفات، 291 تأكيد (scenario 207 · units 16 · costs 59 · zero-transfer 4 · labor-multistage 5) — كلها ناجحة |

### المبادئ المعمارية (قرارات مثبّتة)
1. **المستند هو مصدر الحقيقة:** كل مستند (`DOCS.*`) له `validate / post / unpost`. التعديل = عكس الأثر القديم + ترحيل الجديد في نفس الـ transaction. الإلغاء = عكس + `status='void'`. لا حذف.
2. **اعتماد عند الحفظ** (بدون مسودات) — ما عدا سعر المتر الشهري (مسودة ← معتمد).
3. **القيود تلقائية** من المستندات، والحسابات من «ربط الحسابات» (13 مفتاح `acc_*`) أو من الكود (المراحل، الخزن، فئات المصروفات).
4. **جدول `cost_lines` الموحّد** بيغذي كل تقارير التكلفة (مشروع × بند × مرحلة × تصنيف).
5. **المخزون بالمتوسط المرجح** + إعادة تقييم بأثر رجعي (`recost` / `settle`) + منع الرصيد السالب.
6. **الفترات المالية:** أي ترحيل/تعديل/إلغاء بتاريخ في فترة مقفولة مرفوض.
7. **كل التكويد من الإعدادات فقط**، والعاملين master واحد.
8. **تنفيذ كل طلبات الكتابة واحد ورا التاني** (طابور في `index.js`) عشان إعادة التقييم تبقى متسلسلة ← نسخة سيرفر واحدة فقط.

│  │  ├─ costing.js       ← «تكاليف»: سعر المتر الشهري GRC/GRP + snapshot

│  │  ├─ templates.js     ← «نماذج القيود» (توثيق فقط — مش بتحرّك الترحيل)
│  │  └─ seed.js, opening-seed.js ← تهيئة أول تشغيل + ترحيلات لمرة واحدة

├─ public/                ← PWA: index.html, sw.js, manifest, css/app.css
│  └─ js/ app.js (الـ shell والـ NAV) · core.js (مكونات UI + api) · docs-ui.js (شاشة مستند عامة) · pages/*.js
├─ seed/                  ← دليل الحسابات CSV، الأصناف، الأرصدة الافتتاحية، مقترحات

```

### مسار الطلب (مثال: حفظ إذن صرف)
```
المتصفح → POST /api/doc/stock_issue
  → [طابور الكتابة] → [تحقق الجلسة sid] → docRouter.allow(صلاحية الصفحة.الإجراء)
  → saveDoc(): tx { validate → insert رأس+أسطر → post() }
        post(): addMove(out) → settle() → recost بالمتوسط المرجح
                → onRecost للمستندات المتأثرة بأثر رجعي
                → buildIssue(): cost_lines + postJournal (Dr WIP المرحلة / Cr المخزون)
  → audit() → رد JSON
```

## 4) تدفق البيانات (من المستند للتكلفة للتقرير)

```
 طلب شراء → أمر توريد → إذن استلام / فاتورة شراء ─────────────┐
                                                               ▼
                                      stock_moves (دفتر المخزون بالمتوسط المرجح)
                                                               │ إذن صرف (مشروع+بند+مرحلة)

                                              cost_lines  (جدول التحليل الموحّد)

## 6) الصلاحيات والأمان (ملخص)
- مفاتيح `module.page` (رؤية الصفحة) و`module.page.action` (زر) — المدير يملك الكل؛ المستخدم القديم بيتحوّل من الموديولات.
- الجلسة: كوكي `sid` (HttpOnly, SameSite=Lax) ← جدول `sessions`.
- كلمات المرور: scrypt + salt.
- الإجراءات الحساسة بصلاحيات منفصلة: إعادة فتح إذن معتمد، قفل/فك الأرصدة الافتتاحية، تعديل ربط الحسابات، استيراد الدليل، اعتماد/إعادة فتح شهر التكاليف.
- نقاط الضعف الموجودة موثقة في **AUDIT_FINDINGS.md**.
